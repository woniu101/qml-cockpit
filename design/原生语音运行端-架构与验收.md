# 原生语音运行端

## 边界

运行端使用 Qt/C++、sherpa-onnx C API 和 ONNX Runtime C API。界面、录音、会话、媒体、车控和设备回执仍沿用各自模块；训练与模型导出保留 Python。运行程序不启动 Python，不读取训练源码，也不保留 Python 推理后备路径。

| 模块 | 职责 |
|---|---|
| `AssistantInference` | 每个后端的工作线程、延迟加载与模型复用、取消令牌、主线程结果通知、模型文件校验 |
| `NativeAsr` | Paraformer 离线识别，复用 recognizer，每次创建独立识别流 |
| `NativeWake` | 关键词流、发音表、自定义词校验、流标识隔离及录音回放 |
| `NativeNlu` | rbtl3 的三个输出头，精度与文件由模型描述指定；输出意图/槽位提案，不执行车控 |
| `BertTokenizer` | 中文切分、WordPiece、大小写/重音处理、原句 Unicode 码点偏移 |
| `BioDecoder` / `NluSlots` | BIO 解码、既有受限温度修复、数值完整性和类型/单位/范围校验 |
| `NativeVoice` | ZipVoice 参考音频、分句生成、音频拼接和取消 |
| `NativeAudio` | 有界 WAV/PCM 读取、声道处理、重采样与原子 WAV 保存 |

QML 不持有推理会话或线程。推理结果经原有 `AssistantNlu`、`AssistantVehicle`、`AssistantMedia` 路径校验及执行。取消后旧任务的完成通知不再进入会话。库调用在工作线程内串行，关闭时等待任务退出后释放模型。

## 运行与依赖

原生 SDK 固定为 sherpa-onnx 2.0.1 官方 Windows x64 /MD Release 包，包含兼容的 ONNX Runtime DLL。`scripts/setup-native-inference.ps1` 下载并校验固定 SHA-256。CMake 从 `.deps/assistant-native` 取头文件和导入库，并将运行 DLL 复制到可执行文件旁。

开发运行使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run-assistant.ps1 -External
```

启动脚本只配置 Qt 路径、模型清单和日志位置。`runtime/assistant/models.json` 指向各后端的模型目录，以及默认参考音色。运行目录不依赖相邻 `ai-assistant-test`；该研究目录仅用于导出和验收样本。当前仍是开发运行目录，未生成便携包。

代码也支持可执行文件旁的 `assistant/models.json`，用于以后正式部署。自动化测试在 `CAR_TERMINAL_NO_SETTINGS=1` 时允许用显式模型目录覆盖清单，测试不读写用户偏好。

## 模型更新

训练完成后，在训练环境运行：

```powershell
..\ai-assistant-test\.venv\Scripts\python.exe tools\export-assistant-runtime.py `
  --research ..\ai-assistant-test --output runtime\assistant
```

新 NLU 导出可通过 `--nlu-model <目录>`、`--nlu-precision fp32|int8` 和 `--candidate-model <目录>` 指定。目前默认选取开发验收的 v8-classifier FP32 与单窗试点 v7 INT8，不自动选择训练目录中编号最大的模型。各 NLU 目录必须包含 `inference.json`（`cockpit-nlu-engine-v1`），显式指定 ONNX 文件名和精度。

导出工具复制模型、词表、标签、阈值、分词配置和发音资源，生成各目录的 `bundle.json`，最后发布总清单。运行端首次加载后端前校验文件 SHA-256；NLU 同时校验输出维度与标签配置。单窗试点只有导出模型指纹与既有验收记录一致时才启用，原有逐句核对与用户确认继续保留。

更新时退出程序，将完整导出目录切换为新版本，再启动验收；不要只覆盖正在使用的单个 ONNX 文件。相同模型契约内可更新资源而不重编 C++；新增意图、槽位类型或改变输入输出契约，需要同步扩展代码并验收。

## 本轮体验修复

- “主驾温度调高到二十八度”等明确的绝对温度表达可直接解析，保留温区、半度步进、范围和否定校验。
- 下一首、上一首、暂停、继续、音量和进度等明确媒体指令复用同一份语法直接处理，避免额外等待 NLU。成功播放音乐/视频及常规媒体调整默认只显示文字，错误和需用户处理的情况继续按播报偏好回复。
- 回复不再静默截取前 200 字。ZipVoice 按标点和长度分段生成后完整拼接，取消由原生令牌中断。文字展开只影响界面展示，不改变合成文本。
- 等待补全或确认的计时在语音生成与播放期间暂停，播报结束后重新留出完整的回答时间。显式取消、关闭会话和切换输出设备仍可中止播报。
- ASR 模型驻留复用，去除每句话的解释器、模块导入和模型重载。NLU 不再导入训练侧 PyTorch/Transformers。

## 验收方法与限制

`NativeInferenceTests` 使用训练环境导出的参考样本比较 token ID、原句偏移、语义类别、意图、实体与提案。参考导出脚本为 `tools/export-nlu-parity.py`，不会由运行程序调用。

另有原生 ASR 重复回放、长回复分句生成及末尾音频转写，以及既有车控、补全、取消、模拟器回执、音乐/视频和音色保存测试。原生迁移先使用相同权重验收，后续扩充训练单独记录，避免将运行端变化与模型变化混在同一次比较中。

原生迁移基线：默认 `build` 中 8 组 CTest 全部通过；媒体/助手集 26 项无跳过。v6-bio 与 v7 共 839 条对照的 token、偏移、类别、实体和提案一致。14 个 QML 组件加载无警告。另验证了模型校验和不符、越界路径、带符号数值和不完整数值的拒绝。

本机回放 3.26 秒指令音频，ASR 模型构造约 1.79 秒，首次纯识别 65 ms，复用后 69 ms。该数字不含录音、端点等待、文件解码、模型清单校验和设备响应。界面已用原生版实际执行「主驾温度调高到二十八度」，设定显示 28℃，语音生成与播放流程完成。没有进行真人录音。

性能数字需区分模型加载、纯推理、录音端点等待、文件解码和播放调度。短 ASR 的毫秒级推理结果不能代表整个语音交互耗时。ZipVoice 的合成速度仍受 CPU、参考音色和文本长度影响，迁移 C++ 不保证长回复实时生成。真人麦克风、扬声器回声、远场误唤醒、蓝牙设备和实际听感仍需硬件测试。

验收报告保存在相邻研究目录的 `reports/native-*.log`、`native-nlu-*-parity.json` 和差异报告中，最终构建与测试结果以实际运行记录为准。

使用 `scripts/verify-assistant.ps1` 可在开发目录重跑包含模型与录音样本的完整测试。它明确要求模型、当前模型的对照文件、音乐、视频和模拟器样本存在，避免遗漏资源后静默跳过；不会使用 Python 推理。训练更新记录单独见 [NLU v8](NLU-v8-训练与部署.md)。
