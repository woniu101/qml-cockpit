# Windows 电量与网络接入：实现与验收

日期：2026-11-02。开发调试版本；本轮未生成便携包，未提交或推送 Git。

## 本轮结果

| 来源 | 能量 | 挡位、行驶与车身 | 本地偏好与媒体 |
|---|---|---|---|
| 内置演示 `internal` | 本地模拟 SOC、55 kW / 60 kWh 补能模型 | 本地模拟 | 保持可用 |
| 电脑映射 `system` | Windows 实际电池 SOC 和供电/充电状态；明确无电池时模拟回退 | 继续本地模拟；真实 SOC 不受虚拟行驶与快进影响 | 保持可用 |
| 外部模拟器 `external` | 独立程序的遥测与回执 | 独立程序的遥测与回执 | 保持可用 |

真实网络状态在三种来源下均独立更新。启动默认内置演示；来源不持久化。顶部“数据源”、设置中的“车辆数据来源”和命令行 `--source=internal|system|external` 均可选择来源，兼容已有 `--external`。

来源切换要求 P 挡，自动演示期间禁止切换；外部失联后即便最后挡位是 D 也允许离开外部来源。切换时取消原来源的在途控制和动作。离开电脑映射恢复进入前的模拟能量，离开外部模拟器恢复保存的本地车辆状态；音乐、空调、音量和显示偏好保留当前值。

## 电源读取与映射

`SystemStatus` 通过 `GetSystemPowerStatus` 读取电池存在、百分比、交流电、充电标志与节电状态，每 2 秒刷新，收到系统电源消息时立即安排刷新。休眠前标记能量未就绪，恢复后重新采样。

| 系统结果 | 车机行为 |
|---|---|
| 电池供电 | 实际整数 SOC；模型不显示插枪；虚拟行驶只推进里程和导航 |
| 外接电源且正在充电 | 插枪、线缆、光点、车底光晕和分段 SOC 动效；补能页显示系统正在充电 |
| 外接电源但未充电 | 保留插枪，停止能量流动，明确显示未充电 |
| 100% 且系统停止充电 | 显示满电，停止能量流动 |
| 系统明确无电池 | 显示“无系统电池 · 模拟电量”；使用保存的模拟 SOC，开放模拟补能；交流电不作为插枪信号 |
| 读取失败 / 状态未知 / 信息不全 | 保留最后确认值，显示等待，停止能量流动及行驶；首次无有效 SOC 显示“—”，续航显示未提供 |
| 运行中电池消失 | 恢复保存的模拟能量并暂停行驶，不强制改变挡位 |
| 行驶演示中检测到接通电源 | 速度归零、保留挡位，提示挂 P 挡查看补能 |

未知电池标志 `255` 先于“无电池”位 `128` 判断，避免把未知误判成台式机。实际 SOC 可独立确认，但只有电池、SOC、交流电与充电状态均完整且一致时能量才就绪；不允许“交流电已断开却正在充电”的矛盾样本驱动动效。

无电池回退只在系统明确报告无电池时发生。实际电池读取失败不会开始模拟充电或耗电；已经进入无电池回退后发生采样失败，会保留该模拟来源，并标注“电源状态未知 · 继续模拟电量”。再次检测到电池后恢复实际映射。

真实电池模式隐藏模拟插枪、目标、开始/暂停和快进控件；后端同样拦截能量写操作、演示快照恢复与重置。Windows 未提供的车辆充电功率、预计时间显示“未提供”，目标显示“由系统管理”。虚拟 90% 目标不会停止系统实际充电。电量以系统整数精度展示，续航仍使用 `SOC × 5.2 km`，页面明确标注估算。

首页、电池图标、行驶页、通知、补能页与 3D 使用相同能量状态。原有电量分区、充电与暂停动效保留；未知数据不伪装成 0% 或默认 82%。

## 网络信息

使用 Qt `QNetworkInformation` 的 Windows 系统后端读取可达范围、连接介质、网络认证与流量计费。顶部合并为一个网络入口，根据类型显示有线、Wi-Fi、蜂窝、离线、多网或未知；点击进入“电脑电源与网络”详情。

部分后端不提供连接介质时，结合活动接口和 Windows `GetIfEntry2` 的硬件接口标志判断。仅存在一种可明确判断的物理连接时选用该类型；多个无法判断主路径的活动接口显示多网；仅有虚拟或其他接口时保留未知。离线与“只有局域网”分别展示。详情只列活动接口名称和类型，不保存地址、密码或配对凭据。

网络可达范围由系统报告，实际服务是否可用由后续请求结果决定。本轮没有主动联网探测、网络开关、Wi-Fi 配置或 RSSI 采集；Wi-Fi 图标表示类型，详情标明信号强度未提供。

本阶段交付时蓝牙为占位；2026-11-03 后续已增加适配器/已配对设备只读状态及本地音乐输出选择，见 [后续验收](蓝牙状态与本地音频输出-验收.md)。手机配对操作交给 Windows，A2DP 接收与系统主音量控制仍未实现。

## 验证结果与复现

构建通过；CMake 的 `VehicleStateTests`、`VehicleLinkTests`、`VehicleSystemTests` 三组测试通过。系统状态测试包含：

- `255` 未知、`128` 无电池、有效和矛盾充电标志。
- 真实 64% SOC 不被虚拟行驶/充电/快进改变，目标和插枪操作被拦截。
- 92% 接电未充电、读取失败保留最后值、初次未知不显示虚拟 SOC。
- 无电池回退、重新检测电池、移除电池时停止行驶、P 挡来源切换和本地状态恢复。
- 网络类型、认证与计费字段独立于车辆能量，外部来源不被系统电量覆盖。

系统 UI 使用可控样本，在默认渲染循环、100% 与 125% 缩放下通过真实鼠标交互，检查三种来源、共享 SOC、只读补能、无电池、未知、多种网络图标及详情。100% 下完成一次完整检查；末次 125% 检查另覆盖通知中未知续航的显示。截图和日志位于 `artifacts/system/native/`、`artifacts/system/dpi125/`。这些是测试样本，不代表本机存在电池或 Wi-Fi。

原有双进程 UI 联调通过，覆盖四窗、SOC/速度、充电到目标、拒绝、超时、遥测过期、重连、模拟器重启和内置状态恢复。内置 UI 另做默认渲染 125% 回归，跳过重复演示的耐久部分。

```powershell
.\scripts\build.cmd
# 状态测试，不启动 GUI：
& 'D:\Qt\Tools\CMake_64\bin\ctest.exe' --test-dir build --output-on-failure
.\scripts\verify-system.ps1
.\scripts\verify-system.ps1 -Scale 1.25
.\scripts\verify-link.ps1
.\scripts\verify-native.ps1 -DpiOnly
```

本机实际只读采样保存在 `artifacts/system/live.json`：Windows 明确报告没有系统电池、接通交流电；网络后端为 `networklistmanager`，有线以太网、系统报告可访问互联网。另用 Windows 设备枚举确认电池数量为 0、物理 Realtek 以太网接口处于 Up 状态，与采样一致。车机因此显示电脑映射下的模拟电量回退及真实有线网络。

尚未完成的实体硬件验收：笔记本电池实际充放电与插拔电源、实体 Wi-Fi 断连/漫游、有线与无线切换、休眠唤醒。相关分支已用样本覆盖，需对应硬件再验证。

采集本机状态或打开开发界面：

```powershell
.\scripts\run.cmd --source=system --system-probe
.\scripts\run.cmd --source=system
```

`--system-probe` 只采样并退出，输出不纳入 Git。没有修改模拟器代码或协议，也没有操作 Windows 的电源、网络或蓝牙设置。

## 官方接口依据

- [Microsoft：SYSTEM_POWER_STATUS](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-system_power_status)：交流电、电池标志、百分比和节电字段。
- [Qt：QNetworkInformation](https://doc.qt.io/qt-6.12/qnetworkinformation.html)：系统网络可达范围、介质和可用特性。
- [Microsoft：GetIfEntry2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getifentry2)：接口信息与硬件标志。
