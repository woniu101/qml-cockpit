# 蓝牙状态与本地音频输出：实施与验收

本文保留第一阶段的状态读取与本地音频验收记录。后续已接入手机音乐接收，当前实现及实机结果见 [手机蓝牙音乐接收](手机蓝牙音乐接收-验收.md)。

日期：2026-11-03。本轮对应已确认计划的第 1、2 项。构建、四组 CTest、100% / 125% 设备界面及 125% 原有音乐/车控回归已通过；桌面解锁后已补齐界面验收。蓝牙物理适配器、手机音频接收与人工听感的边界另述如下。

## 已实现

| 部分 | 行为 |
|---|---|
| 顶栏蓝牙 | 从灰色静态占位改为可点击状态入口；开启时强调色，有设备连接时显示小点 |
| 蓝牙详情 | 开启/关闭/禁用/无适配器/未知/受限/错误；适配器及经典、低功耗蓝牙已配对设备；配对与连接分别显示 |
| 蓝牙采集 | Windows SDK C++/WinRT，后台 MTA 查询；异步操作 3 秒超时；设备/电源消息、打开面板、手动刷新、10 秒校准 |
| 无硬件判定 | WinRT 空集合再结合 SetupAPI 当前蓝牙设备枚举；无法确认时显示未知，不把读取失败当无适配器 |
| 音频入口 | 音乐页“音频输出”、底栏扬声器、蓝牙面板“本地音乐输出” |
| 本地路由 | QMediaDevices 活动输出列表；选择 QAudioOutput 的实际设备，或跟随系统默认 |
| 设备变化 | 显式设备不随默认变化；移除后回退默认，清除失效偏好；设备重新出现不自动切回 |
| 没有输出 | 暂停本地播放、禁用播放入口、拦截其他播放请求；恢复设备后等待用户操作 |
| 偏好与音量 | 输出选择保存在本机；沿用应用音量，不修改系统默认设备、主音量或其他应用音量 |

蓝牙只查询已配对设备，不扫描未配对设备、不自动开启无线电、不主动配对或连接。系统设置按钮仅打开相应设置页面。设备连接不代表手机媒体接收已建立，界面明确说明手机音乐接收暂不可用。

配对设备的连接字段不可用时显示未知；读取失败、访问受限或超时分别反馈。当前无 QtBluetooth 模块，使用已安装 Windows SDK，无新增下载依赖。

## 实测和测试样本

本机采样：`artifacts/devices/live.json`。

- 系统返回蓝牙 `absent`，无适配器、无连接设备；与本机当前 PnP 枚举一致。
- 系统有 2 个音频输出：`2476W1 (NVIDIA High Definition Audio)` 和 `数字输出 (High Definition Audio Device)`，默认是前者。
- Qt 当前路由与选择匹配。探针不导出设备 ID、地址或配对凭据，不播放音乐、不改变系统输出。

四组 CTest 通过：原有车辆状态、协议、电脑映射及新增 `DeviceServicesTests`。新增覆盖：

- 默认/显式选择、系统默认变化、移除回退、空设备列表、失效设备选择拒绝及偏好隔离。
- 蓝牙各种状态、已配对但未连接、连接状态未知；键盘连接不声明手机音乐连接。
- 两个真实 QAudioDevice 的静音播放路由，播放器持续处于播放状态且进度不倒退、应用音量保持 0。
- 使用真实设备对象模拟拓扑移除，触发暂停；重新提供设备列表后不自动播放。

自动音频验证使用静音 WAV 和音量 0，证明 Qt 路由及播放器状态，不作为人工听感确认。初始验收时尚无蓝牙适配器，因此开关、已配对连接和权限错误使用样本；之后新增适配器的实机记录见下文。物理耳机插拔和 Windows 默认设备切换尚需实机事件验收。

明细输出 `artifacts/devices/unit.txt`：6 个 QtTest 项通过（含初始化/清理），两个实际路由均检查，无跳过项。另以 `offscreen` 平台实例化音频面板、蓝牙面板、音乐页、信息栏、底栏与音乐卡，QML 绑定检查通过，Qt 窗口对象数为 0，无桌面输入；证据 `artifacts/devices/qml-check.json`。该检查不验证实际字体、画面或鼠标操作。

## 界面验收结果

`DeviceSmoke` 与 `scripts/verify-devices.ps1` 在默认渲染循环的 100% / 125% 缩放下均通过：覆盖蓝牙各状态面板、配对/连接区分、音乐页和底栏入口、实际输出选择、无输出/恢复、1120 × 630 最小窗口。实际鼠标事件点击首个输出后，Qt 配置的设备与选中目标一致；切换实际输出保留播放和进度，所有输出移除样本触发暂停，恢复后不自动播放。

已逐图核对音频列表、蓝牙开启/设备列表、无音频输出、两类最小窗口画面，未出现文字越界、按钮遮挡或选中态错误。`artifacts/devices/native/`、`dpi125/` 保存截图及 `verification.json`：两次运行均有 2 个实际输出、检查 2 个实际路由，最终路由匹配。蓝牙连接和插拔拓扑为标注来源的样本，自动播放为静音，均不冒充实体蓝牙或物理插拔验收。

`verify-native.ps1 -DpiOnly` 原有音乐/车控回归通过：本地解码、播放/暂停/切歌/进度、门窗、导航、充电、行驶、双指缩放及 1120 × 630 操作均保留；本轮跳过重复演示耐久部分。没有新增 QML 运行时警告。

另以实际数据启动开发版并连接原模拟器，手动点击顶栏蓝牙入口，确认显示“未检测到蓝牙适配器”；从该面板进入本地音乐输出，实际列出两个输出，当前为跟随默认显示器音频。保留原本地音量 45% 和暂停状态，未操作系统设置、修改默认输出或自动播放。开发版留在音频输出面板便于查看。

## 官方接口依据

- [Qt QMediaDevices](https://doc.qt.io/qt-6/qmediadevices.html)：活动设备与默认设备变化通知。
- [Qt QAudioOutput](https://doc.qt.io/qt-6.12/qaudiooutput.html)：选择本地播放器输出及应用音量。
- [Microsoft Radio.GetRadiosAsync](https://learn.microsoft.com/en-us/uwp/api/windows.devices.radios.radio.getradiosasync?view=winrt-22621)：无线电快照及桌面架构/空集合边界。
- [Microsoft 蓝牙配对状态查询](https://learn.microsoft.com/en-us/uwp/api/windows.devices.bluetooth.bluetoothdevice.getdeviceselectorfrompairingstate?view=winrt-26100)：使用已配对筛选条件。
- [Microsoft SetupDiGetClassDevsW](https://learn.microsoft.com/en-us/windows/win32/api/setupapi/nf-setupapi-setupdigetclassdevsw)：当前设备枚举。
