# v5 实施与验收记录

日期：2026-11-02。实施依据为《车机演示交互优化方案 v2》。本轮完成离线演示范围，外部车辆与联网服务未接入。

## 对应最初三个问题

1. 全局反馈从状态栏中的 y=9 移至独立内容反馈区 y=83，高度 52–64；标题位于左侧，导航引导和右侧面板从 y=165 开始，单窗操作主要就地反馈。
2. 四角卡片用描边表示选中，状态以完整文字和百分比表示；车门、备厢等动作明确命名，快捷控制拆为独立页面。
3. 百分比入口在“车辆 → 车门车窗 → 车窗”。0% 为全关，100% 为全开；滑条、数字输入和 0/15/50/100 预设均可使用，运动中出现停止按钮。实际界面输入精确 35% 已验证。

## 阶段交付

| 阶段 | 本轮交付 |
|---|---|
| A 交互稿 | `交互规格.md`、`states/` 中四种车窗状态稿；最终布局以本轮实际运行截图验收 |
| B 车窗与反馈 | 四窗实时/目标开度分离，统一进度驱动玻璃、数值与提醒；拖动预览、松手确认、预设、中停、批量关闭/通风；部件标记及反馈区域 |
| C 离线流程 | 驻车/挡位/车速与导航独立；不同目的地示意路线；补能目标/SOC/续航/功率；音乐行点击及循环/导入/重试；偏好保存、时间问候、通知信息分级 |
| D 视觉与演示 | 可动后视镜、简化充电口与插枪；材质与接地阴影；双指缩放、命名视角、自动定位开关；加载回退/重试；日夜主题、画质档位；12 步演示暂停/单步/变速/退出恢复 |

启动尺寸会限制在当前显示器工作区内；1120×700 等非标准比例居中缩放，保留完整底栏。125% 缩放下使用逻辑坐标映射输入。

## 验证方法与证据

- 后端状态测试：实时窗位、停止、重置取消过期结果、批量操作、行驶互锁、路线独立、充电目标、空调恢复、通知、媒体语义、偏好落盘与演示隔离。
- basic 渲染循环界面测试：实际鼠标、键盘及合成双指输入，精确 35% 数字输入、滑条、预设、中停、通知定位、车门动作、充电流程、真实本地音源解码/暂停/切歌/跳进度及窗口缩小。
- 图像比较：对比同一 3D 区域，确认玻璃、后视镜、充电口和插枪实际改变画面；检查全降玻璃仍有窗框标记。未用直接调用 `setWindow(35)` 代替百分比入口验收。
- 默认渲染循环及 125% DPI：同一套界面测试；默认 DPI 下额外重复 3 轮、每轮 12 步演示并核对恢复的电量与偏好。
- 故障回退：测试主动设置渲染失败状态，检查静态预览，再由界面点击重新加载并等待 3D 恢复。这覆盖界面恢复路径，不等同于验证所有显卡驱动故障。
- 夜间标题颜色另设可读性检查，避免 Qt Controls 的同名 Label 覆盖本地主题标签。

证据位于项目根目录 `artifacts/v5/`：`test.log`、`native.log`、`dpi125.log` 及对应截图目录。主要截图：

- `basic/03-window-35.png`：精确 35% 与模型玻璃、窗框标记。
- `basic/04-window-stopped.png`：中途停止。
- `basic/07-batch-progress.png`：全局反馈区域。
- `native/13-mirrors-folded.png`、`native/14-port-open.png`、`native/15-charging.png`：部件动画和补能。

触控使用 Qt 合成的双指事件测试；未连接实体触摸屏。重复演示属于短时回归，未进行数小时的老化或真实车载系统验证。

## 性能实测

机器：Windows 11、i7-12700KF、NVIDIA GT 730 2 GB、约 32 GB 内存。默认 Windows 渲染后端由日志记录；每档画质在热身后连续旋转 4 秒，统计 frameSwapped 时间间隔与进程工作集。数值代表该电脑当时的运行环境，不能视为所有设备的性能承诺。

后端为 D3D11，使用 GT 730。实测结果如下（FPS 为旋转期间呈现帧间隔均值）：

| 缩放 / 窗口逻辑尺寸 | 标准 FPS / p95 帧时 | 高画质 FPS / p95 帧时 | 工作集 / 峰值工作集 |
|---|---|---|---|
| 100% / 1600×900 | 53.5 / 28.6 ms | 41.3 / 33.0 ms | 456 / 477 MiB |
| 125% / 1504×762 | 45.4 / 33.0 ms | 37.6 / 34.2 ms | 473 / 506 MiB |

原始数据见 `artifacts/v5/native/performance.json` 与 `artifacts/v5/dpi125/performance.json`。工作集在两档测量完成后读取，不代表单个页面独占内存。标准档采用中等 MSAA，高画质增加 AO 和 MSAA；默认使用标准档。采样时间较短，p95 帧时用于显示波动，未据此声称稳定 60 FPS 或无内存泄漏。

## 交付边界

原始 Tesla GLB 保留不变，分离出的后视镜保留原顶点/UV/材质。新增充电口、枪与线缆为简化演示机构，未做原车型机械精度复原。源文件、分离记录及 CC BY 4.0 署名随项目保存，发布包包含署名与许可。

本轮未加入方案中注明为后续扩展的座椅位置/通风和通知历史；天气、连接图标仍为展示内容。联网地图/音乐、蓝牙配对、Wi-Fi、CAN、手机互联、语音与真实车辆回执不在本轮离线范围。可见充电、电量、行驶与路线均为本地模拟。

发布目录：`dist/CarTerminal/`；便携压缩包：`dist/CarTerminal-Windows-x64.zip`。

打包验收：开发版和发布版 EXE 的 SHA-256 一致；将 PATH 限制为 Windows 系统目录并清除 Qt/QML 插件路径后，发布版通过默认渲染循环的实际界面测试（退出码 0）。这确认本机运行时依赖可由发布目录提供；未在另一台全新 Windows 电脑上安装测试。证据为 `artifacts/v5/release.log`。打包脚本同时复制操作说明、交互规格、验收记录和模型署名许可。
