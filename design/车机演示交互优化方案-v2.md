# 车机演示交互优化方案 v2

> 实施更新：本方案已按用户“执行”指令落地为 v5；原检查结论保留作实施依据。当前完成范围、实际截图与验证记录见 [实施与验收记录](v2/实施与验收记录.md)。

日期：2026-11-02。检查依据：用户截图、当前 QML 页面、VehicleState 状态逻辑与已有测试代码。本轮只形成方案，未修改应用源码或发布包；未重新执行性能测试。

## 一、当前三个问题的结论

1. **轻提示确实过高。** 当前位于 1600×900 逻辑画面的 y=9，直接进入时钟、电量所在的 65 像素状态栏。上一轮位置调整得过高了。应在状态栏下方设置独立反馈区域，并重新安排标题、锁车信息和导航车道提示的避让。
2. **状态与动作表达混在一起。** 四位置卡片的绿色表示“选中”，大按钮的绿色表示“可执行”，其他开关的绿色又表示“开启”。“开启/关闭”缺少具体对象；低透明度的“关闭”既像不可用，又容易被理解成当前状态。
3. **百分比入口确实未完成。** 底层 setWindow(index, opening) 接受 0–100，3D 玻璃位置也已绑定这个数值；但车辆页仅发出 0 和 100，没有开度滑条。15% 通风函数只在底层和测试中调用；测试中的 50% 也通过底层直接设置，不能证明界面已有入口。

## 二、优先重做门窗控制与反馈

### 1. 反馈位置与出现规则

- 全局反馈放在状态栏下方、主内容区上沿的独立留白区。1600×900 设计中先以顶部约 85–100 像素作为静态排版候选，最终通过全页面稿确定；不直接只修改 y 坐标。
- 页面标题保留左侧；车辆页重复的锁车入口整理到控制区；导航页车道引导为反馈区留出空间。
- 单个车窗的升降过程与结果主要在选中部件旁反馈，例如“右后车窗 · 当前开度 40%”。减少每次操作都抬头找提示的情况。
- 全车操作完成、操作受限、媒体错误等使用全局反馈。普通完成约 1.8–2 秒，受限提示约 4 秒；持续状态保留在控件和通知中心。
- 同类重复反馈合并；警告优先。被警告压住的完成结果仍在对应部件区域可见，避免静默丢失操作结果。
- 提示区域不截获模型拖动或按钮输入；长文本可换行，并适配日夜主题与窗口缩放。

### 2. 右侧控制区重新分工

当前面板下半部始终放着门锁、后备厢、充电口，直接增加百分比会继续挤压空间。建议拆清内容：

| 页面/模式 | 核心内容 |
|---|---|
| 快捷控制 | 真正独立的快捷网格：门锁、前后备厢、后视镜、充电口、通风、全部关窗 |
| 门窗—车窗 | 四窗选择、当前开度、开度滑条、常用预设、停止、全部关窗 |
| 门窗—车门 | 四门选择、当前门状态、具体开/关门动作、门锁状态 |
| 充电 | 充电口、插枪/充电演示状态、目标电量和补能信息 |

四位置选择增加车头方向标识，左右始终按车辆自身方向定义；旋转模型不会改变位置定义。

### 3. 百分比与动作的具体设计

右侧车窗区按以下顺序排列：

```text
车窗 / 车门

四个位置选择（带车头方向）

右后车窗
当前开度 40% · 部分开启

0% 全关  ━━━━━●━━━━━━  100% 全开

全关    通风 15%    半开 50%    全开

正在调整时：当前 40% → 目标 70%    [停止]

全部关窗
```

- 百分比统一定义为**开度：0% 全关，100% 全开**，支持 1% 步进。
- 四个位置卡片负责选择对象，显示“全关 0% / 通风 15% / 开度 40% / 全开 100%”。
- 窗户动作明确使用“全开、全关”；车门使用“打开右后车门 / 关闭右后车门”；备厢使用“打开后备厢 / 关闭后备厢”。
- 当前状态独立显示，动作按钮描述将执行的动作。到达端点的预设用选中标记说明，保持文字可读；重复点击不再执行或弹出成功提示。
- 拖动滑条时数值与 3D 同步；一次拖动结束只产生一次完成反馈。预设操作使用平滑升降动画，支持中途停止。
- 车门和前后备厢本阶段保持开/关控制，百分比先用于车窗。

### 4. 状态与动画统一

当前 windows 存放请求目标值，随后 QML 玻璃动画和 C++ 完成定时器分别运行，没有独立的实时开度。

应区分目标开度、模拟当前开度、动作状态（空闲/升起/降下/停止/受限）。3D、滑条、数值、位置卡片和通知共用同一个动画进度来源。固定距离采用一致的升降速度，短距离调整相应缩短耗时。重置、切页、连续输入和停止都需要明确的取消规则。

这一阶段仍是本地车辆演示；模拟当前值不包装成真实车辆传感器回执。

## 三、全程序检查清单

优先级定义：P0 为当前直接影响理解和操作的问题；P1 为形成完整离线演示所需的流程；P2 为视觉、设置和扩展体验；外部服务接入单独评估。

| 范围 | 当前已实现/存在的问题 | 优化方案 | 优先级 |
|---|---|---|---|
| 统一交互 | 已有高亮、执行中限制和三类反馈；颜色含义重复，禁用文字偏淡，轻提示进入状态栏 | 统一“选中、动作、状态、警告”的样式，重排反馈区，统一具体动作文案 | P0 |
| 车窗 | 有四窗目标值、升降动画和全部关闭；界面只有 0/100，缺滑条、预设、停止和实时开度 | 落地上面的完整车窗控制区，打通四窗、3D 和通知 | P0 |
| 驻车/导航 | parked 等于未导航；导航开始即显示固定 58 km/h，结束即驻车 | 将挡位/车速/驻车与导航分开，支持驻车规划路线、行驶中继续导航的独立演示 | P1 |
| 快捷控制 | 与门窗模式共用同一面板 | 独立快捷网格，减少跨分类查找前备厢、后备厢、通风等功能 | P1 |
| 空调/座椅 | 双区温度、风量、AUTO、A/C、除雾、加热已存在；座椅页只有加热开关 | 先补双区同步和加热档位，明确除雾退出的恢复规则；座椅位置/通风作为后续扩展 | P1/P2 |
| 灯光/后视镜 | 灯光有单个开关和模型发光；后视镜仅状态切换 | 灯光分组与清楚的模式状态；后视镜补可动网格，界面与模型一致 | P1 |
| 充电 | 只有充电口状态与附近站点；电量 82%、续航 426 km 固定 | 建立离线补能流程：未连接、已插枪、充电中、完成，补目标电量、功率和剩余时间 | P1 |
| 导航 | 地图、路线、车标、转弯和目的地入口已存在；所有目的地仍复用固定路线、12 km/18 分钟，首页“回家 28 分钟”与之不一致，车道文字固定 | 不同目的地采用一致的演示路线数据；统一里程、ETA、转向与车道提示，核对车标与路线贴合 | P1 |
| 音乐 | 本地播放、暂停、切歌、拖动进度和音量已存在；当前曲目行显示暂停图标，但点击该行会调用播放/选曲逻辑，不会暂停 | 统一行点击和图标行为；补加载/空列表/重试入口，循环模式和本地导入后续扩展 | P1/P2 |
| 通知 | 已按部件状态动态生成、消除并支持跳转；只有当前提醒，没有历史，普通提醒也用对勾汇总 | 区分正常、信息、警告；明确角标是当前提醒数；近期操作记录可选增加 | P1/P2 |
| 设置/时钟 | 日夜切换、全屏、恢复初始状态已存在；偏好不保存，深夜仍会显示“上午好” | 保存温度、音量、主题等偏好，运行中的门窗状态启动回默认；修正时间段问候，增加自动主题选项 | P1/P2 |
| 自动演示 | 固定 9 步、每步 3 秒循环；未提供暂停、单步和速度控制 | 演示与手动操作明确分离，增加暂停/继续、单步、速度，以及退出后的恢复规则 | P2 |
| 3D/触控 | 已有旋转、滚轮缩放、部件高亮和自动转向；内饰固定相机，未见双指缩放入口；白车层次偏弱，接地阴影为固定贴图 | 增加自动定位开关、触屏手势、命名视角；玻璃完全下降后在窗框保留选中标记；校准玻璃、轮毂、车漆与接地阴影 | P1/P2 |
| 加载/适配 | 当前主要按固定画布整体缩放；未见 3D 失败回退、触屏键盘入口和画质档位 | 补加载占位与失败回退、输入焦点/键盘、不同 DPI 和宽高比排版；性能实测后决定画质策略 | P2 |

蓝牙、Wi-Fi、天气、联网音乐、真实地图和 CAN/硬件接入目前不在已实现范围。建议先完成可信的离线演示闭环，外部服务另开阶段，明确接口、授权和运行平台后再接入。

## 四、实施与交付顺序

### 阶段 A：重做交互稿

交付：车辆页、导航页、音乐页的反馈区排版，以及车窗 0%、40%、100%、执行中四种状态稿。先解决反馈位置、右侧空间和操作语义，再进入开发。

### 阶段 B：P0 功能闭环

交付：开度滑条、0/15/50/100 预设、中途停止、实时开度、3D 同步、统一提示和独立快捷控制布局。将来开发应优先检查 Main、FeedbackBanner、VehiclePage、VehicleScene 与 VehicleState 的职责划分。

### 阶段 C：完整离线流程

交付：独立的驻车/导航状态、目的地路线数据一致性、充电演示、音乐点击语义修正、基本偏好保存、时间问候修正、通知信息层级。

### 阶段 D：视觉与展示质量

交付：后视镜/充电口模型部件、3D 材质和阴影、触屏手势、加载回退、不同 DPI 适配、可控演示脚本。帧率与内存完成实测后再给优化结论。

## 五、阶段 B 的验收条件

1. 用户能直接找到任一车窗的百分比入口，操作 35% 后，数值、3D 和通知一致。
2. 任一车窗在 0%、15%、50%、100% 下都有明确文字状态；左右位置不随模型旋转改变。
3. 执行中按“停止”可停在当前模拟开度，状态不会跳回旧目标。
4. 滑条连续拖动、快速切换车窗、全部关闭、切页和复位后，不出现过期完成提示或错误部件状态。
5. 玻璃完全下降后，仍能辨认选中了哪个窗位。
6. 提示不遮挡状态栏、页面标题、导航引导、模型操作或底栏；长消息及夜间主题同样可读。
7. 普通单窗操作就地反馈，全车操作和受限行为有适度全局提示；一次操作不反复弹成功消息。
8. 补充真实界面操作测试，不再仅通过底层直接设置 50% 来验证百分比功能。

已有状态测试与鼠标冒烟测试继续保留；新增滑条、停止/重定向、触摸、高 DPI、长时间运行和默认渲染模式的验证。
