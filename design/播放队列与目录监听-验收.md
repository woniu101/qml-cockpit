# 播放队列、随机历史与目录变化

日期：2026-11-03。Windows / Qt 6.12 / MSVC 开发版。沿用现有音乐库和播放器，未生成便携包。

## 使用与行为

| 功能 | 入口与规则 |
|---|---|
| 建立队列 | 在音乐库点击歌曲，将当时分类、搜索结果及排序固定为队列；此后浏览其他分类、调整搜索不改变正在播放的范围。再次从新的列表选择歌曲可重建队列。 |
| 查看与编辑 | 音乐页上方“播放队列”：显示来源和数量，当前曲目高亮；可点击播放、上下移动或移除待播歌曲。当前曲目不可移出，移出队列不影响库或文件。 |
| 切歌 | 顺序循环按队列排序；单曲循环在自然播放结束时重播，手动切歌仍切换曲目；缺失或已移除的条目跳过。队列无可用音源时暂停并提示。 |
| 随机与历史 | 一轮内优先选未播放歌曲；多首可用时跨轮不立即重复。上一首回到实际历史，再下一首沿已有历史前进；历史起点保持当前并提示。本次运行最多保留 500 个历史记录，不跨重启保存历史。 |
| 保存 | 保存显式队列、顺序和来源标签；重启恢复曲目与位置并保持暂停。未建立显式队列时，默认范围随音乐库增加。 |
| 目录管理 | 音乐库下方“目录管理”，或队列面板“查看音乐目录”：添加、查看状态和曲目数、重扫、停止、移除。 |
| 移除目录 | 仅移除归属该根目录的独占库条目；其他已添加根目录共同管理及单独导入的歌曲保留。正在播放的曲目被移除时暂停。原文件保留。 |
| 文件新增 | 自动发现已添加目录的多层子目录及新音源；后台读取属性和封面，规范化路径去重。 |
| 文件缺失与恢复 | 标记不可用，当前音源缺失时暂停；保留索引和收藏。原路径恢复后重新可用，等待手动播放。移动或改名后的新路径会作为新条目导入，旧条目保留不可用状态，不猜测文件身份。 |
| 重新定位 | 失效条目可选择新文件；保留收藏、队列顺序和历史中的身份，当前位置归零、保持暂停。旧路径加入排除记录，重扫不重复加入。 |
| 歌词变动 | 当前曲目的同名 LRC/TXT 新增或修改会自动刷新；内容未变化时不重置歌词滚动。仍提供手动刷新入口。 |

歌曲仍可放在任意可访问的目录，包含多层子目录。无需复制到项目或应用安装目录。目录、文件及队列的移除分别处理，均不删除磁盘文件。

## 监听与开销

- 文件通知合并 500 毫秒，另每 5 秒后台检查。自动检查无变化时不重建曲目列表、不重新载入歌词、不弹扫描完成提示。
- Windows 上，多层原生目录监听可能妨碍祖先目录重命名。实现保留外层目录监听，并用后台递归检查覆盖深层变化；测试验证整棵根目录移动和恢复。深层变化通常在下一次检查处理，索引耗时取决于规模和磁盘速度。
- 文件大小、修改时间和外部封面指纹未变化时复用已有属性，避免每次检查重新读取全部 Windows 标签和缩略图。
- 单次扫描最多 50,000 个音频文件，不跟随目录符号链接；非 Windows 平台的详细监听最多补充 1,024 个目录，其余由定时检查覆盖。
- 停止扫描保留已处理条目，并暂停自动扫描；后续文件通知或手动导入/重扫可再次启动。设备恢复不触发自动播放。
- 音乐库原子保存格式沿用版本 1，新增队列和单独导入来源字段；兼容原有索引。异常索引保留，不静默覆盖。

## 验证

1. `MusicLibraryTests` 共 12 个通过项（含初始化/清理），覆盖原有歌词、索引、标签和封面，以及分类队列、顺序和索引变化、随机不重复和前后历史、缺失音源跳过、共享与手动导入目录归属、自动发现嵌套新文件、文件消失/恢复、根目录整体移动/恢复、歌词自动刷新、队列重启恢复、队列编辑保留历史、重新定位路径替换。
2. CTest 全部 6 组通过，覆盖原有车辆、协议、Windows 映射、蓝牙接收与实际音频路由。
3. `verify-music.ps1` 在 100% 和 125% 缩放通过：原创静音 WAV 实际解码、歌词跳转、搜索收藏、最小窗口、队列面板打开与调序/移除、随机历史、目录管理与移除原文件保留；另启动独立进程验证实际播放器恢复 6 秒位置并保持暂停。
4. 新音乐管理面板纳入无窗口 QML 创建检查；检查组件绑定，不替代实际界面验证。
5. `verify-devices.ps1 -Scale 1.25` 验证本地路由、手机接收期间本地播放互斥、断开与输出恢复后不自动播放。
6. `verify-native.ps1 -DpiOnly` 整车回归通过：车控、导航、行驶、补能、队列顺序切歌、实际播放器解码和进度跳转、演示恢复及最小窗口。

界面证据：`artifacts/music/native/08-playback-queue.png`、`09-directory-manager.png`、`10-directory-removed.png`；125% 证据位于 `artifacts/music/dpi125/`。原有音乐和独立进程断点证据保留。

目录移动和断开恢复使用临时目录及真实文件操作测试，未将其表述为物理 U 盘拔插验收。文件被其他程序占用时，能否移动仍取决于 Windows 和该程序的文件共享方式。

## 复验

```powershell
.\scripts\build.cmd
& 'D:\Qt\Tools\CMake_64\bin\ctest.exe' --test-dir build --output-on-failure
.\scripts\verify-music.ps1
.\scripts\verify-music.ps1 -Scale 1.25
.\scripts\verify-devices.ps1 -Scale 1.25
.\scripts\verify-native.ps1 -DpiOnly
.\scripts\run.cmd --device-qml-check
```

Qt 的监听可能随文件或目录移动、删除而失效，并存在平台资源限制，因此实现结合重新注册和定时检查。接口依据：[QFileSystemWatcher](https://doc.qt.io/qt-6.12/qfilesystemwatcher.html)。
