# 车机终端静态设计稿 V1

本轮交付三张同一视觉体系的静态设计稿，用于确认布局、车型气质、配色、字号与信息层次。未修改运行中的 QML 界面。

## 查看设计稿

- `screens/01-parking.png`：驻车首页。车辆、续航和电量构成主体，右侧安排目的地、音乐和场景入口。
- `screens/02-navigation.png`：行车导航。转向信息与路线为主，保留媒体、行程和定位工具。
- `screens/03-vehicle-controls.png`：车辆控制。左侧选择设置类别，中间定位车辆部件，右侧显示对应操作。

每张逻辑尺寸为 1600 × 900；同目录 `@2x.png` 为 3200 × 1800 高清版。SVG 保留可编辑文字、图形和自包含的车辆图片。

## 三屏状态

三屏沿用同一位用户、同一时间、82% 电量与 22.0° 双区温度。导航页的地点和路网为静态示意，用于评审布局，并非真实地理路线。音乐专辑图为代码绘制的原创图形。

车控页当前选中左前车窗，状态为已关闭；开启为主要操作，关闭显示不可用状态；四个车窗支持分部件选择，全部关闭为独立操作。

## 车辆素材的用途

`assets/vehicle-pearl.png` 使用内置 imagegen 生成，透明背景，无品牌，四门电动轿车，所有部件处于关闭状态。生成方式和完整提示词见 `vehicle-prompt.md`。

这是一张用于静态视觉评审的二维渲染图片，不是可旋转的 3D 模型。后续 QML 实现需要选用或整理相符的 GLB/glTF 车辆资产，再校准镜头、车漆、玻璃、阴影和部件轴心。静态稿用于明确目标效果。

## 编辑和重新导出

- 修改 `source/build_designs.py` 可统一调整布局、文字、图标和配色。
- 运行该脚本生成 `screens/*.svg`。
- 使用 Node.js 运行 `source/render.cjs`，需要 `sharp` 包，生成标准与高清 PNG。
- SVG 可以在支持 SVG 的设计工具中打开；车辆是嵌入图片，其他主要元素为矢量文字和图形。

## 评审重点

1. 驻车首页的车辆气质、大小和默认视角。
2. 三屏的信息密度、中文阅读尺度和留白。
3. 绿色强调、浅色背景及统一底栏是否适合作为下一版基准。
4. 行车与驻车之间的主任务切换是否明确。
5. 车控页面的部件定位与右侧操作是否对应。
