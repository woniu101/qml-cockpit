# 媒体中心开发与验收

日期：2026-11-03。对应第一阶段“媒体重构 + 网络电台 + 本地视频”。第二阶段语音/AI 与动态助手形象尚未接入。

## 使用入口与界面

底栏“音乐”升级为“媒体”，页内为音乐、电台、视频和手机蓝牙四个入口，全部应用也可直接进入对应子页。沿用现有主题、信息栏、圆角和留白。首页、导航、行驶页共用一张媒体卡，根据当前来源显示；视频离页暂停，不在首页继续播放小视频。

音乐保留原有库、收藏、目录、队列、随机历史、歌词和断点。手机蓝牙保留连接界面，不显示未取得的远端歌曲元数据。原 MusicPage/MusicCard/VehicleQueue 实现已由拆分后的模块替代，未添加 Vehicle 媒体代理层。

电台采用独立的台名和直播状态布局，无假进度条、射频信号或调谐尺。视频默认为缩略图网格，进入后显示可收起列表；全屏在应用内容区域内隐藏顶栏/底栏，Esc 或显式返回退出，F11 仍负责窗口全屏。

## 模块职责

| 模块 | 职责 |
|---|---|
| MediaState / MusicQueue | 音乐元信息、音量、进度、队列、随机历史与媒体偏好 |
| MediaSession | 唯一前台 QMediaPlayer，来源替换、延迟跳转、能力、视频驻车限制、输出丢失和蓝牙互斥 |
| RadioService | 类型化频道模型、收藏/最近、切台与最多三次有限重试 |
| RadioSourceResolver | 广播机构目录访问、临时直播 URL、请求取消与响应校验 |
| VideoLibrary | 视频索引、书签、目录/最近浏览、后台缩略图与文件变化 |
| MediaDirectory | 音乐与视频共用的路径规范化、去重、可取消递归遍历 |
| MusicLibrary / MusicSource | 保留音乐专有的标签、歌词、文件监听与特殊本地容器只读适配 |
| AppRoutes / MediaPage / Overlays | 命名页面标识、媒体子页和弹层路由 |

main.cpp 只装配这些对象，绑定 Windows 音频/手机接收和车辆策略。VehicleState 不保存音量、曲目、进度或队列。音量/循环模式从旧 preferences.ini 集中迁入 media-preferences.ini 一次，原音乐索引保持原格式。模拟器协议及仓库未改动。

内部来源使用 C++ 枚举与专用模型；QML 接收展示属性。当前范围没有增加运行时插件加载器、云鉴权或 AI 依赖。未来网络视频需增加来源解析与生命周期，而不是绕过现有本地 URL 校验。

## 网络电台

首批频道为中国之声、经济之声、音乐之声、香港电台第一台。央广从公开播放器目录解析，港台从官方播放器页面公布的 HLS 地址解析；都与 QML 展示代码分开。台源配置是外部依赖，需要随广播机构变化维护，不保证永久地址。

- 央广目录：`https://apppc.cnr.cn/national`；官方公开播放器配置是接口依据。
- 港台页面：`https://www.rthk.hk/radio/radio1`。
- 临时签名地址不存入用户偏好；每次开始/重连重新解析。
- 目录请求限时 10 秒、响应上限 2 MiB；播放缓冲超时 12 秒。
- 失败最多重试三次，间隔 1/2/4 秒。停止、切台、切换来源和退出取消旧请求及计时器；来源代号隔离晚到回调。
- 收藏、最近和最后选择台存于应用数据目录的 media/radio.json；启动不自动播放。
- 直播不提供时移或进度拖动，未接入节目单、节目曲目信息、真实 FM/AM 硬件或录播回退。

## 视频库与播放

通过文件多选、目录或拖放导入，递归包含子目录；不跟随符号链接，单次最多 50,000 个文件。文件不复制到源码仓库。扩展名筛选为 MP4、MKV、WebM、MOV、AVI、M4V、MPEG、MPG、WMV；后缀不是可解码承诺。

后台单任务读取时长/标签并生成预览，单个新文件最多等待 5 秒，扫描可取消。缩略图最长边框为 560×315，图像输入限 4,000 万像素；生成缓存预算 128 MiB。扫描清理已无索引引用的生成缩略图；达到预算后新条目使用默认图，不无限扩张磁盘占用。

播放页保持原比例，支持暂停、跳转、±10 秒、0.5/1/1.25/1.5/2 倍速、音量、列表收起与全屏。无音轨明确标注，音量控件禁用；有音轨但没有音频输出时暂停。音轨/内嵌字幕选择以 Qt 返回的轨道为准，字幕文本显示在视频区域。无视频轨道的文件给出错误状态。

media/videos.json 保存索引、目录、最后观看时间、时长和位置。更新合并写入，最近观看排序每五秒至多更新一次。接近片尾三秒内的书签归零；启动恢复索引并保持暂停。每五秒后台检查新增/失效/恢复；当前文件失效暂停，恢复后不自动播放。移除索引与目录不删除原文件，缺失条目可重新定位。

播放要求同时满足 P 挡、车速为零和车辆来源有效。D/R/N、非零速度或外部数据过期会暂停并退出媒体全屏；返回 P 后手动继续。返回视频库、切换媒体子页或离开媒体中心都会暂停。

100% 与 125% 的媒体检查均包含最小 1120×630 窗口及夜间截图。静态设计稿保留于 design/media，实际运行截图在 artifacts/media，二者分别记录。

本轮后段 Windows 报告的音频输出数量为零：正式界面的电台/有声音乐播放按策略禁用。媒体测试单独创建生产 MediaSession 和解码缓冲接收器，验证真实官方直播解析/解码；不会伪造系统扬声器。报告中的 audioOutputAvailable 与 radioValidation 区分完整界面播放和无硬件的解码验证。设备测试在无输出时跳过实际路由/手机接收界面动作，并在报告标明。先前已有输出时的蓝牙接收实测仍见原蓝牙验收文档，本轮不新增听音结论。

测试收尾曾发现 QtMultimedia 访问异常。转储定位到跨两个播放器复用的 QAudioBufferOutput 在析构时访问已结束的探测播放器。测试改为每个播放器独立接收器，且接收器先于播放器销毁；没有通过延时隐藏异常。正式退出流程先停止并解绑视频/音频输出，再销毁 QML 视图。需结合进程退出码判断测试成功，不能只读取 PASS 日志。相关对象关联可查 [Qt 播放器源码](https://github.com/qt/qtmultimedia/blob/dev/src/multimedia/playback/qmediaplayer.cpp)。
