# 全局能量信息与模型叠层优化方案

日期：2026-11-03。依据：实施前 QML 源码与用户提供的后视镜页面截图。方案已按用户确认实施，本文保留排查依据与设计规则，实施结果见第 7 节。

## 1. 实施前排查结论

浮动电量卡来自共享的 `VehicleScene.qml`，不是各个页面分别实现。该组件默认 `showEnergyBadge: true`，模型就绪、非行驶场景且插枪时显示 `EnergyBadge.qml`，固定在模型视图区左上角。

实施前首页单独关闭了该卡；车辆页仅在第 5 类“充电补能”中关闭。其余五个分类继续显示，车内视角也未排除。这使充电信息与后视镜、灯光、空调等当前任务争夺注意力，固定的卡片位置也无法适应旋转后的车身轮廓。

| 页面/场景 | 实施前表现 | 主要问题 |
|---|---|---|
| 首页 | 大号电量/续航、透明充电摘要、模型动效；无浮动电量卡 | 基本层级已合理，可保留 |
| 快捷控制 | 插枪时出现模型左上电量卡 | 与当前操作分离，遮占模型留白 |
| 车门车窗 | 同上，另有选中门窗的模型标记 | 能量卡、部件标记和右侧控制并存，信息过多 |
| 座椅空调 | 同上 | 充电卡与舒适性操作关联弱 |
| 外部灯光 | 同上，模型同时展示灯光效果 | 充电光晕/电量条会分散对灯光的注意力 |
| 后视镜 | 同上，与用户截图一致 | 大卡片比当前操作提示更醒目 |
| 充电补能 | 浮动卡已隐藏，右侧有详细电量与控制 | 方向正确；标题下与充电口标记仍可精简重复文字 |
| 车辆页车内视角 | 非补能分类仍可显示电量卡 | 卡片与车内观察无直接关系 |
| 行驶页 | 通过行驶模式隐藏电量卡，左侧仪表显示 SOC/续航 | 保留仪表；图像左上的道路状态提示可收敛进现有标题说明 |
| 导航、音乐页 | 无模型电量卡，沿用全局顶栏 SOC | 保持当前内容布局，补齐全局能量详情入口即可 |
| 附近充电站浮层 | 有电量、续航；电量颜色固定为绿色 | 与低电量分区颜色不一致；电脑实际电量模式下续航应标注估算 |
| 车辆通知浮层 | 汇总能量和当前部件提醒 | 保留概览价值；不承担常驻充电面板的职责 |

## 2. 统一展示原则

建议采用“顶栏随时可看，首页提供摘要，补能页负责详情，模型服务当前操作”的分工。允许必要的总览与详情共存，但不在所有模型画面复制完整电量面板。

### 全局顶栏

- 保留电量百分比与电池图标，保持现有整体排版。
- 真正充电时在电池组内显示小闪电，接电未充电时显示静态连接标识；不增加第二个信息胶囊。
- 点击电池组进入补能详情，只负责导航，不改变挡位或充电状态。
- 低电量使用统一强调色；未知显示“—”；过期保留最后值并通过现有数据源状态与详情明确标注。
- 无电池时沿用明确的模拟电量回退标签，不把台式机交流电映射成插枪。

### 首页

保留当前大号 SOC/续航和一行透明摘要。充电中显示状态、可用功率、预计时间与“查看补能”；暂停、达标、满电和过期使用同一位置切换文字。保持当前模型位置，不再叠加浮动卡。普通断枪状态且没有提醒时，摘要区域保持留白。

### 车辆页五个非补能分类

全部移除模型左上电量卡，不用新的充电横条替代。标题下保留当前部件信息，右侧继续展示本分类的控制。

- 选中门窗、备厢等部件时，只保留一个定位标记。
- 未选中具体部件时不额外生成泛化状态气泡。
- 全局充电状态通过顶栏查看；需要详细控制时点击顶栏电池进入补能页。

### 充电补能页

右侧面板集中显示状态、SOC、续航、目标及操作。模型区域保留充电口的简短名称或定位点，用于说明接口位置；“正在充电 / 已连接未充电”等实时状态放在右侧，减少同一句话在标题下、模型旁和面板内重复。

标题下可简化为“充电口 · 左后侧”。当接口不可见或处于车内视角时隐藏定位标记。状态异常仍在右侧说明，受限操作沿用现有短暂提示。

### 导航、音乐和行驶

导航和音乐沿用全局电池入口，不新增充电卡。行驶保留左侧 SOC/续航仪表；道路模型区的小状态说明可合并到现有页头，车速/数据过期由仪表和现有状态说明表达。模型不叠加与行驶任务无关的补能装饰。

### 附近充电站与通知

附近充电站电量颜色使用统一分区，电脑实际电量对应的续航标注“估算”。通知浮层保留必要概览和可定位的提醒；低电量、达标或失联等事件不在多个页面重复生成常驻卡片。

## 3. 模型动效按任务区分

| 场景 | 推荐保留 | 推荐收起 |
|---|---|---|
| 首页、补能页车外 | 插枪、线缆、充电流动光点、适度光晕和分段能量示意 | 完整浮动电量卡 |
| 其他车辆分类车外 | 实际插枪与线缆、充电口状态灯、当前选中部件标记 | 地面分段电量条、大范围呼吸光晕和抢眼的流动特效 |
| 车内 | 车内观察与对应交互 | 电量卡、外部充电标记、地面充电装饰 |
| 行驶 | 路面、车轮及行驶相关反馈 | 补能装饰动效；继续遵守插枪不得开始行驶的现有规则 |

插枪几何用于表达真实连接，不能因为切换到后视镜页就消失。暂停、目标完成、满电和数据过期统一停止能量流动；保留最后确认的连接状态。当前任务之外的充电装饰降低存在感。

## 4. 精度、颜色与状态文案

1. 顶栏与首页采用同一整数口径，详情采用一位小数。建议整数向下取整，避免 99.9% 提前显示 100%；满电状态始终依据真实 SOC 和实际充电状态判定。电脑原始整数 SOC 保持整数精度。
2. 所有页面使用 `EnergyVisual` 的分区色和状态文案，包括附近充电站浮层。未知不能显示成低电量或默认演示电量。
3. 接电未充电、正在充电、目标达成、真正满电、数据待更新分别表达；达到 90% 目标不称为满电。
4. Windows 未提供的功率和预计时间继续显示“未提供”。外部遥测过期时不把旧功率继续显示为实时功率。
5. 短暂操作反馈沿用状态栏下方的保留区；实时状态就地更新，避免 SOC 每变化一次都弹提示。失败与受限原因就近说明，重要事件也可从通知入口查看。

## 5. 实施范围与顺序

第一批优先处理跨页面一致性：

- 从共享 `VehicleScene` 移除 `EnergyBadge` 实例及相关开关，清理相应资源和回归引用，避免新增页面再次默认出现。
- 全部六个车辆分类采用统一的模型叠层规则；补能状态只在补能右侧完整展示，部件标记简化。
- 顶栏电池增加状态识别与详情入口；模型动效区分完整展示、环境提示和关闭三个级别。

第二批处理细节：

- 统一整数/小数显示、低电量颜色、估算续航标识和异常文案。
- 收敛行驶画面内的重复说明，检查浮层与操作反馈层级。
- 整理旧方案中“其他车身页保留浮动卡”的说明，使文档与最终规则一致。

本次不需要改模拟器协议、能量计算、车身控制或原来的 SOC 分区。首页模型继续采用当前右 40px、上 45px 的偏移。

## 6. 验收清单

- 插枪后逐一切换快捷控制、门窗、座椅空调、灯光、后视镜、补能，以及车内/车外视角：均无浮动电量卡。
- 开门、升降窗、折叠后视镜及灯光操作时，部件标记清晰，不与充电说明重叠。
- 首页与补能页能直观区分充电、暂停、目标达成、满电、断枪与数据过期；其他分类保留真实连接几何并减少装饰。
- 顶栏电池入口在首页、导航、车辆、音乐和行驶中均可打开详情，不触发实际控制。
- 检查 0%、10%、20%、80%、90% 目标、99.9%、100% 和未知样本；检查 Windows 只读及无电池回退。
- 默认渲染 100%/125% 与最小窗口下，卡片、说明、模型及底栏不重叠；继续沿用已有充电和失联联调回归。

## 7. 实施结果

第一批与第二批均已实施。`EnergyBadge.qml`、共享场景实例及开关、CMake 资源条目已删除。首页保持右 40px、上 45px 的构图偏移。

- `VehicleScene.energyDetail` 默认环境提示，首页/补能页显式完整展示，行驶页关闭装饰。接口灯可在其他车外分类表达充电，地面光晕、电量段和线缆光点仅在完整展示场景启用；车内隐藏外部充电几何与标记。
- 顶栏电池新增键盘可聚焦的 132 × 44 操作区域，原数字与电池位置保持不变。闪电/插头/刷新分别表达充电、接电未充电、等待数据；点击仅定位补能页。
- 模型旁充电标记简化为“充电口”，标题下为“充电口 · 左后侧”，实时充电文案集中在右侧。其他分类不再显示泛化的“车辆外观”说明。行驶画面内的小状态卡并入页头说明。
- `EnergyVisual` 集中整数向下取整、详情小数、未知与过期色彩；99.99% 详情仍显示 99.9%，不提前显示满电。附近充电站统一分区色，Windows 模式标注估算续航及实际电量来源。

本轮继续使用开发版，无便携包；模拟器协议、能量模型与已有 SOC 分区不变。
