# 媒体中心与语音助手：分阶段开发方案

日期：2026-11-03。根据当前已提交的代码评估，本文是设计和实施计划，不是完成清单。

用户补充：FM/AM 可采用网络广播实现。因此建议第一阶段为“媒体架构整理 + 网络电台 + 本地视频”，第二阶段为“语音设备控制 + 语音回复 + 可选动态形象”。本地音乐、视频保持离线，电台是明确联网的例外；未来允许增加其他网络媒体来源。

执行进度：阶段 1A 已完成 12 张静态画板与独立台源能力原型，见 [设计稿与真实台源验证](media/README.md)。阶段 1B–1E 的媒体重构、网络电台、本地视频和统一媒体卡已接入正式程序；具体已测范围与尚未完成的项目见 [开发与验收](媒体中心-开发与验收.md)。第二阶段语音助手尚未开始，本文后续章节保留原方案与验收目标，不应全部视为已完成。

## 1. 当前结构与重构必要性

已检查 `src/main.cpp`、`VehicleState.h`、`VehicleQueue.cpp`、`MusicLibrary.h`、`VehicleExternal.cpp`、`qml/Main.qml`、`BottomBar.qml`、`Overlays.qml` 和当前 CMake 配置。

| 现状 | 新功能带来的问题 | 建议 |
|---|---|---|
| VehicleState 保存歌曲、播放状态、进度、队列和随机历史 | 电台、视频再接入会继续扩大车辆对象职责 | 将媒体状态、队列和书签迁入独立媒体模块，VehicleState 保留车辆领域 |
| main.cpp 直接连接播放器、音量、断点恢复和蓝牙互斥 | 增加直播重连、视频输出和语音后难以追踪状态来源 | main 仅做启动与对象装配，播放生命周期由 PlaybackSession 管理 |
| MusicLibrary 同时负责扫描、索引、歌词和播放协调 | 直接复制为 VideoLibrary 会复制文件监听和持久化问题 | 提取有限的目录扫描、索引和缓存基础设施，音乐歌词与视频缩略图保留各自处理器 |
| 页面依赖数字索引，Overlays 使用长条件链选择弹窗 | 页面及入口增加后容易出现错误跳转 | 使用类型化页面标识、明确的路由表和弹层宿主，整体替换旧内部用法 |
| 蓝牙是系统音频接收，其他音频是应用内播放器 | 不能把所有来源都当成可暂停、可跳转、可调音量的文件 | 独立来源适配器，按实际能力显示控制并统一协调播放占用 |
| 车辆控制与外部回执已有实现 | 语音若直接改字段，可能绕过互锁并过早播报成功 | 第二阶段接入前抽取统一命令入口，触屏与语音调用同一规则 |

重构按可运行的垂直切片进行：先迁移一个功能并回归，再移除旧实现。不保留新旧两套播放器、两套媒体状态或永久的 Vehicle.playing 转发层。文件数据若变化，保留必要的一次性迁移；已实测的“前置 ID3 + M4A”只读播放能力应搬入媒体来源解析器，不能因重构丢失。

## 2. 整体界面

### 2.1 导航与风格

保持浅色背景、鼠尾草绿、深绿文字、留白与现有圆角；夜间继续使用统一主题。视频画面区域允许深色，其外围仍跟随系统主题。

- 底栏四个主入口采用“首页 / 导航 / 车辆 / 媒体”，将“音乐”升级为“媒体”，不另外挤入电台和视频图标。保留双区空调与音量位置。
- 媒体页顶部使用“音乐 / 电台 / 视频 / 手机蓝牙”分段导航。来源内容分开，播放状态和声音策略统一。
- 顶栏只放系统和车辆状态，不放电台、视频等应用入口。第二阶段助手入口放“全部应用”面板及可自定义快捷位，避免首期强塞底栏；语音硬件按键可后续映射。
- 全部应用中提供音乐、电台、视频的直接入口，进入同一媒体中心的对应子页，不复制页面。
- 首页保留一张媒体卡，随当前来源显示歌曲、正在收听电台或“视频已暂停”。不添加一组相互竞争的媒体卡。
- 内容页内部采用 Layout 和少量布局令牌，保留当前逻辑画布机制；统一页边距、标题基线、按钮高度和面板间距。主操作触控区域以 48 个逻辑像素左右为起点，在最小窗口与 125% 缩放下校验。

### 2.2 各媒体子页

| 子页 | 主区域 | 辅助区域与行为 |
|---|---|---|
| 音乐 | 封面、歌名、歌词、进度和播放控制 | 音乐库、搜索、队列、目录管理；保留当前功能，减少重复状态标签 |
| 电台 | 台标、台名、可用时的地区/频率、网络直播状态、播放/停止、上一收藏台/下一收藏台 | 全部、收藏、最近收听，搜索与分类；连接/缓冲/断线就地显示 |
| 视频 | 默认以海报网格浏览，点击进入宽屏播放页 | 搜索、文件夹、最近观看、继续观看；播放页提供可收起的列表，不常驻挤占画面 |
| 手机蓝牙 | 手机名称、音频连接状态与连接管理 | 保留已验证的连接界面；未取得真实曲目时不显示歌名、封面或假进度 |

媒体中心保持一个页面标题和一层主要导航。不同内容使用适合的布局，不要求音乐、广播和视频机械套用同一块“封面 + 进度条”。

### 2.3 视频播放体验

- 默认保持原视频比例，避免裁切画面；支持适应、原比例、全屏。全屏以 Esc 退出，保留显式返回入口；控制栏操作后可自动收起。
- 顶部显示片名和返回，底部显示进度、播放/暂停、前后跳转、音量及全屏；无音轨时明确标记，允许静音视频正常播放。
- 视频仅在 P 挡且车速为零、车辆状态有效时允许播放。进入 D/R/N、速度变化或外部车辆数据过期时暂停并显示原因；重新驻车后由用户主动继续。
- 离开视频页默认暂停并保存位置，不在首页自动播放缩小视频；音乐和电台切换到导航页后可继续收听。

## 3. 网络广播实现 FM/AM 风格

### 3.1 概念与显示

网络流可以提供真实电台内容，无须 FM/AM 接收硬件，但不会产生真实调谐频率、射频信号强度或搜台行为。FM/AM 在第一阶段是频道属性与界面风格，实际来源明确标注“网络直播”。只有电台目录有可靠依据时才显示如 FM 频率，不为网络独立频道编造频率。

不建议首版放一条很大的模拟频率尺：多个网络台未必能按当地频率排列，列表和收藏比虚拟调谐更直观。后续如用户希望增加收音机风格，可做可选的收藏台轮盘，不显示假的实时扫描或射频强度。

### 3.2 第一阶段范围

1. 独立 StationCatalog，包含稳定电台 ID、名称、台标、地区、分类、可选频率、播放源和可选节目元数据来源。目录数据与 QML、播放器代码分开。
2. 首批只选择少量有明确来源、可直接播放且实测可用的电台。逐条记录来源与验证时间；不依靠网页抓取、猜测 URL 或登录态链接。尚未调研具体台源，不承诺任何指定电台必定可播放。
3. 支持收藏、搜索、最近收听、上一/下一收藏台。首期没有真实节目接口时，仅显示台名和直播状态，不伪造主持人、节目单、歌曲或封面。
4. 播放状态分为未播放、连接中、缓冲中、正在收听、重连中、离线、地址不可用；网络状态只作提示，最终播放结果以播放器反馈为准。
5. 默认“播放 / 停止”。停止后再播放重新接入当前直播；不承诺时移暂停或拖动进度。直播源能力变化由 seekable 等能力驱动，首版不做时移缓存。
6. 断线采用可取消、有上限的重试。切台、手动停止、来源切换和退出时取消旧请求；晚到的旧台回调不能覆盖新台。断线不自动播放本地录音冒充直播。
7. 初期优先验证直接 HTTP(S) 音频流；HLS 按实际站源和 Qt/FFmpeg 后端验证后支持。PLS/M3U 若需要，先解析目录得到真实流地址，不以文件后缀推断可播。

网络广播是新增的联网功能，不改变本地音乐和视频必须离线可用的目标。若仍需无网演示，可以单独增加“录播示例”，明确标注来源和可跳转进度，不与直播状态混用。

### 3.3 未来的真实硬件收音机

只有需要离线接收空中广播时，才增加 USB/其他调谐器的具体适配。应先验证硬件、Windows 驱动、SDK 和音频路由，再接入 Radio 模块；本轮不采购、不安装驱动、不假设普通蓝牙适配器具备 FM/AM 接收能力。

## 4. 本地视频范围

第一阶段完成：文件/目录导入、递归子目录、拖入文件、按文件夹浏览、搜索、缩略图和时长、播放/暂停、跳转、倍速、音量、全屏、继续观看、缺失文件处理，以及驻车限制。

- 建议示例目录 `D:\Projects\car_terminal\media\video`，与现有 `media\music` 平级。允许任意可访问目录，不把个人视频复制到 Git 仓库。
- 文件夹扫描、取消、去重和文件变化检查共用基础模块；视频元数据和缩略图另行提取并限制后台并发、解码时长和磁盘缓存。
- 优先用 MP4/H.264/AAC 和一个无音轨样本验证完整链路，再扩展 MKV、WebM 等测试集；“容器后缀可导入”和“编码可解码”分开，不能承诺任意 MP4 都能播放。
- 书签以稳定媒体 ID 关联文件，保存时间与有效位置；重启保持暂停。接近片尾时标记已看完，不每次停在片尾几秒。
- 内嵌音轨、字幕可先使用 Qt 暴露的轨道选择能力；外置同名 SRT 作为后续一个明确任务，ASS 样式和复杂特效不纳入首个播放器验收。首版不以字幕功能阻塞播放主链路。
- 没有音频输出时，有音轨视频默认暂停等待；静音视频允许显式播放。输出恢复不自动播放。

未来网络视频通过来源解析器接入；下载、鉴权、缓存、过期链接和自适应流不提前实现，也不等于只把 file URL 换成 HTTP 就完成联网视频。

## 5. 模块与依赖

建议直接在 qml-cockpit 仓库按模块组织，不新增电台、视频或助手仓库。模拟器继续只提供车辆数据与故障注入。

```text
src/
  app/          启动装配、页面路由、弹层路由
  media/        PlaybackSession、MediaItem、Capabilities、Queue、Bookmark
    library/    目录扫描、索引、文件监测、缓存与一次性数据迁移
    music/      音乐标签、歌词、随机历史
    radio/      电台目录、流地址解析、重连状态
    video/      视频库、缩略图、轨道与观看记录
  platform/     Windows 电源、网络、蓝牙、音频设备适配
  vehicle/      车辆状态与控制规则、数据来源适配、命令结果
  assistant/    第二阶段新增：收音、识别、意图、会话、回复
qml/
  shell/        主框架、导航、弹层宿主
  components/   统一按钮、导航分段、媒体状态、空态
  media/        媒体容器、音乐、电台、视频和蓝牙子页
  assistant/    第二阶段：语音条、对话面板和形象视图
```

按真实职责迁移，不为了目录整齐一次搬完所有车辆代码。CMake 按模块分目标/源集，平台依赖留在平台目标；助手启用后再添加模型运行时和 TextToSpeech 依赖。

核心边界：

- PlaybackSession 持有一个应用内前台 QMediaPlayer 和音频输出；音乐、网络电台、视频轮流使用。视频视图只绑定/解绑 VideoOutput，不在页面销毁时顺带销毁播放服务。蓝牙接收保留独立系统适配器。
- MediaItem 保存标识、类型、来源、展示信息；来源解析器负责得到可播放资源及生命周期，包含现有特殊本地文件的 QIODevice 只读视图。目录不直接驱动播放器。
- Capabilities 描述实际是否能暂停、跳转、切歌、调音量、读元数据；页面不以来源名堆叠条件判断。直播、文件和蓝牙有不同能力。
- 业务域内部使用类型化 C++ 数据和枚举，QML 边界优先 QAbstractListModel；不把未来所有业务都塞成任意 QVariantMap。
- 声音协调器管理本地媒体、蓝牙接收和第二阶段语音播报的占用，不让各页面互相调用 stop。后台扫描与缩略图只通过受控任务反馈状态。
- 应用使用稳定业务标识，不以页码或列表行号作为持久引用。页面路由由明确枚举/路由表决定；不必引入运行时插件加载框架。

声音策略：

| 操作 | 行为 |
|---|---|
| 从音乐切到电台/视频 | 保存原来源位置，停止原播放，用户选中的新来源取得占用；失败不突然恢复其他来源 |
| 音乐/电台页面切到导航 | 可后台继续，首页媒体卡同步 |
| 离开视频页或不再满足驻车条件 | 视频暂停、保存位置，不自动改播音乐 |
| 连接手机蓝牙 | 暂停应用内媒体；切回本地需显式断开手机接收，维持已验证行为 |
| 输出设备丢失 | 停止可听播放并报告原因；恢复后等待用户操作 |
| 第二阶段语音收音/播报 | 先实现半双工，本地媒体暂停；结束后仅在原会话仍有效、原本正在播放且没有新操作时恢复 |

手机蓝牙声音由 Windows 默认输出承载，现有 QAudioOutput 无法直接控制它。不能承诺它会被同一混音器自动压低或暂停；语音与蓝牙同时播放的降音/回声处理要单独实测，首版可提示用户先在手机暂停，不擅自断开连接。

## 6. 第二阶段：语音助手

### 6.1 最小闭环

按钮唤起 → 麦克风收音 → 本地语音识别 → 意图和参数解析 → 同一车辆命令入口 → 回执/状态确认 → 文字与语音回复。

优先按钮说话，再做常驻唤醒。第一版先解决“听清楚、做对、说实话”，不要求接入大语言模型。固定设备操作以明确的意图和参数实现；以后若增加本地/云端语言模型，只替换意图解析或对话模块，执行层仍使用同一命令规范。

首批命令：全部/指定车窗关闭、指定车窗开到百分比、主驾/副驾温度、空调开关、风量、播放/暂停本地媒体、切到收藏电台、查询电量与窗位。空调目前是车机本地演示，不宣称收到模拟器的真实空调回执。

例如“把左前车窗关上”解析为 `SetWindow(leftFront, 0)`，“主驾调到二十二度”解析为 `SetTemperature(driver, 22)`。目标含糊、低置信度或数值越界时询问，不猜测并执行；“不要打开车窗”等否定语句应有单独测试。

### 6.2 命令与回复

触屏和语音共用 CommandService，统一参数范围、挡位互锁、数据源选择、可用能力与命令编号。

`received → accepted/executing → completed | rejected | failed | timeout` 分开。收到 accepted 可回复“正在关闭左前车窗”，只有实际开度到零/完成回执后才回复“左前车窗已关闭”。超时、拒绝、失联按实际原因回复；迟到的旧结果不能串到新会话。

外部车身仍走既有模拟器通道；内置车辆由本地状态确认；本地空调由自身状态确认。暂不扩展真实车辆硬件或执行任意系统指令。复合指令后续增加逐项结果，不把其中一项成功播报成全部成功。

### 6.3 技术验证

- ASR 优先评估 sherpa-onnx 中文模型与 C/C++ API，配合麦克风输入和 VAD。先验证目标电脑 CPU 下准确率、首字延迟与整句延迟，再确定模型；“支持 Windows”不等于本机已验收。
- TTS 首选系统已安装的中文声音，评估 Qt TextToSpeech / Windows WinRT；本机 Qt 当前未发现 TextToSpeech 头文件目录，需要第二阶段补齐依赖后验证。缺少中文声音时明确提示，不假设一定存在。
- 后续可增加离线 TTS 模型提高音色一致性，ASR/TTS 模型分别核对体积、运行成本和模型许可。默认不把大型模型或录音放进源码仓库。
- 输入和输出设备独立选择；无麦克风、拒绝访问、无扬声器和拔插都有可理解的状态。先采用半双工，播报时不继续识别自己的声音；常驻唤醒、AEC、免按键打断及车内远场噪声属于后续验收项。

第二阶段细分为：2A 文本命令与回执闭环；2B 按钮语音输入及语音回复；2C 唤醒、连续会话与可选动态形象。先用可测试的文本入口确认控制链路，避免同时排查模型、设备和车辆三个层面。

## 7. 卡通形象建议

用户提供的羊角帽人物适合作为可选助手形象：米白、浅棕与当前低饱和主题相容，能增加亲和力。但原图为白色方形背景、完整站姿，小尺寸时脸部辨识度低，不宜直接作为大幅常驻立绘。

- 默认：小型麦克风/声波入口；唤起后在内容区下沿、底部空调栏上方显示轻量语音条，包含听到的文字、当前状态与取消。弹层和重要车辆提醒由统一宿主管理。
- 形象模式：使用透明背景的头肩像或小型半身像，作为语音条的配角；展开对话面板时再显示较完整形象。设置里可关闭，默认不遮挡模型、导航或空调。
- 先做待机、聆听、处理、说话、完成/失败等状态，眨眼、轻微点头和简单嘴型即可。收音状态不等于执行成功，表情跟随真实会话状态。
- 静态原图不能直接变成自然动态立绘，需要透明分层/多帧素材。第一版用 QML 变换配合少量状态素材即可；素材确实需要后再引入 Live2D/3D 或复杂骨骼运行时。
- 动画跟随可见性暂停，支持减少动态效果；人物资源与语音、设备控制解耦，可以替换皮肤而不修改执行代码。

因此建议：可以使用，但第二阶段后半程再做，且以可选、轻量、低干扰为原则。

## 8. 实施顺序与验收

| 里程碑 | 交付物 | 核心验收 |
|---|---|---|
| 1A 界面与台源验证 | 媒体导航、电台页、视频库/播放页、首页媒体卡、空态/错误态静态稿；少量真实台源播放原型 | 日夜、最小窗口和 125% 缩放协调；台源可播、可取消、错误可解释 |
| 1B 媒体重构 | PlaybackSession、来源能力、队列/书签、声音协调、路由与共享目录基础设施 | 现有六首实测音乐、歌词、队列、随机历史、断点和蓝牙接收不退化；旧媒体状态实现移除 |
| 1C 网络电台 | 频道目录、收藏/最近、播放/停止、连接与缓冲、断网/失效及有限重试 | 快速切台不串台；停止后不再重连；直播无假进度/假射频状态 |
| 1D 本地视频 | 导入/子目录、海报、播放、全屏、倍速、书签、轨道基础能力和驻车限制 | 中文路径、不同编码、无音轨、损坏/缺失文件、音频拔插及挡位/过期状态通过 |
| 1E 联合收尾 | 统一首页媒体卡、来源切换、模块文档与测试 | 多来源不叠音、不意外恢复；网络不可用不影响离线音乐和视频 |
| 2A 命令入口 | 触屏与文本语音意图共用的命令及结果模型 | 接受/完成/拒绝/超时独立；不绕过互锁、不误报成功 |
| 2B 语音闭环 | 麦克风、中文识别、设备控制、TTS 和明确状态反馈 | 硬件实测、否定/歧义/数值命令、设备缺失与蓝牙混音边界 |
| 2C 体验增强 | 可选人物状态动画、唤醒与连续会话 | 动画不遮挡、可关闭、低干扰，先通过基础语音指标再扩展 |

每个里程碑保持可运行，完成后再进入下一步。测试集中验证独立规则、来源切换与异步取消，以及实际媒体/设备链路；不以样本成功替代真实电台和麦克风验收。网络回归可使用受控本机流服务复现断流与重连，真实电台单列人工/实机结果，不让外部台源波动主导单元测试。

优先落实 1A 与 1B，不同时启动助手模型集成。调试阶段继续不打便携包；本文和开发约束文件留在工作区，未经本轮发布指令不自动提交/推送。

## 9. 官方技术依据

- [Qt 6.12 QMediaPlayer](https://doc.qt.io/qt-6.12/qmediaplayer.html)：媒体状态、来源、跳转能力、轨道和视频输出；实际编解码能力需后端与文件验证。
- [Qt MediaPlayer QML](https://doc.qt.io/qt-6/qml-qtmultimedia-mediaplayer.html)：缓冲、直播时长、错误与可跳转状态。
- [Qt VideoOutput](https://doc.qt.io/qt-6/qml-qtmultimedia-videooutput.html)：视频呈现与画面缩放。
- [Qt TextToSpeech 引擎](https://doc.qt.io/qt-6.12/qttexttospeech-engines.html)：WinRT / SAPI、系统声音及输出能力差异。
- [sherpa-onnx 官方文档](https://k2-fsa.github.io/sherpa/onnx/) 与 [C/C++ API](https://k2-fsa.github.io/sherpa/onnx/c-api/html/)：本地识别、VAD、TTS 和唤醒能力；具体模型待实测选型。
