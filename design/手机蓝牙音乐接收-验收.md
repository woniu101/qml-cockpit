# 手机蓝牙音乐接收（A2DP Sink）

日期：2026-11-03。基于 Qt 6.12 / MSVC x64 / Windows 原生蓝牙栈，独立于车辆模拟数据源。

后续 Windows 媒体会话和 AVRCP 桥接验证仍未取得本机 vivo 的真实曲目信息；已按用户要求撤回实验性信息适配，恢复本文记录的连接界面。详见 [AVRCP 核验与回退记录](蓝牙曲目信息-原生适配与AVRCP评估.md)。

## 行为与入口

- 顶栏蓝牙入口及音乐页“手机蓝牙音乐”进入接收面板；系统配对后的音频设备列为“可接收音乐的设备”。普通已配对设备另列，不把键盘或鼠标当成手机音频。
- 点击“连接音乐”后创建接收连接，允许取消；接通显示“手机音频已接通”，用户在手机播放音乐。通道已建立不代表正在播放，无虚构曲名、封面、播放进度或流量动画。
- 接收声音交给 Windows 系统默认输出。当前本地输出选择、底栏本地音量不能控制该声音；接收时底栏提示“手机调音量”，系统声音设置可调整默认输出。
- 连接、接收、断开期间暂停本地播放器，隐藏本地播放控制、禁用曲目播放请求。关闭浮层或切页不会断开。取消、连接失败、手动断开、输出恢复后不自动播放本地音乐。
- 不自动配对、开启系统蓝牙、建立音乐连接或重连。退出时释放本应用的接收连接，不删除配对信息，不改变系统默认输出或主音量。

## 实现与异常

`BluetoothAudio` 的后台线程独占 WinRT 接收对象。用 `AudioPlaybackConnection.GetDeviceSelector()` 枚举音频端点，用临时 token 关联内部 ID，ID 不写入偏好或采样报告。连接顺序为 `TryCreateFromId` → `StartAsync` → `OpenAsync`；成功还需 `State == Opened`。

后台枚举每 10 秒及手动刷新时更新，连接状态每 500 ms 校准。枚举、启动、连接分别有 5/10/25 秒上限；使用异步操作的 `Status` 轮询，不重复注册 `Completed` 回调。修正了实机首次尝试触发的 `E_ILLEGAL_DELEGATE_ASSIGNMENT (0x80000018)`。取消或退出会取消尚未完成的操作，版本校验拒绝过时结果。

支持远端断连、音频端点移除、适配器关闭或移除、全部音频输出丢失、系统拒绝、不支持和查询错误。只释放本应用持有的接收连接；保留配对。查询错误与没有设备分别显示。需要 Windows 10 2004+ 及兼容硬件/驱动。

## 自动验证

- `BluetoothAudioTests`：不自动连接、重复连接拒绝、取消与迟到结果、失败重试、断连后不重连、音频输出移除与恢复、活动端点移除、不支持、连接中退出。后端为样本，不冒充实机结果。
- `DeviceSmoke`：接收后端为明确标注的样本，本地音乐使用实际 QMediaPlayer（静音）和实际输出设备；验证连接时暂停、中央播放拦截、断开不恢复播放、恢复输出不重连、手机音乐页与首页入口、最小窗口。
- 100% / 125% 缩放的图片及机器结果位于 `artifacts/devices/native/` 与 `artifacts/devices/dpi125/`；新截图编号 07–10。
- 原有车辆、联调、系统、电量、音频路由测试一并运行。QML 组件无窗口实例化检查用于发现绑定错误。

## 实机记录

适配器 `Generic Bluetooth Radio`（系统设备页标识 CSR8510 A10），驱动正常、蓝牙开启。Windows 及车机均列出 `brave的vivo X200 Pro`，原生接收设备枚举也包含该手机；默认输出为 `2476W1 (NVIDIA High Definition Audio)`。只读报告 `artifacts/devices/live.json` 中的 `phoneAudio` 记录 API 支持情况、候选设备名称及错误，不创建连接。

10:35：修正异步等待后，开发版通过实际按钮连接上述手机，界面进入“手机音频已接通”，候选连接按钮禁用，显示“断开音乐”。首页同步切换为手机音乐，底栏显示“手机调音量”。这是原生 `OpenAsync` 成功且连接对象为 `Opened` 的结果，未使用测试样本。

10:38：实际点击“断开音乐”后经过释放状态回到未连接，“连接音乐”恢复可用；首页恢复本地曲目且保持暂停，底栏恢复本地音量。Windows 设备状态同步回到已配对未连接。

10:39：再次点击“连接音乐”后成功恢复“手机音频已接通”。开发版保留该连接及蓝牙详情页，等待用户手机播放和听音确认。

10:47：用户反馈手机已播放音乐、手机没有外放声音，电脑当前没有接扬声器。只读复核手机仍为设备已连接，默认音频端点仍为显示器 `2476W1 (NVIDIA High Definition Audio)`，另有数字输出。系统列出音频端点不等于已接可出声的物理设备；本次无法完成人工听音验收，不能以手机静音单独证明音频已实际传输。需接入耳机或扬声器并选择正确的 Windows 默认输出后继续试听。只读 probe 自身不建立接收连接，报告中的 `phoneAudio.phase=idle` 不代表正在运行的车机连接状态。

实际出声和手机播放/暂停需接入输出硬件后听音确认。物理拔插、手机端主动断开和应用退出的实机效果尚未逐项验收，对应生命周期已有后端样本测试。未实现通话、AVRCP 远端控制或远端曲目信息；不生成便携包，不提交或推送代码。

## 复验

```powershell
.\scripts\build.cmd
& 'D:\Qt\Tools\CMake_64\bin\ctest.exe' --test-dir build --output-on-failure
.\scripts\verify-devices.ps1
.\scripts\verify-devices.ps1 -Scale 1.25
.\scripts\run.cmd --device-qml-check
.\scripts\run.cmd --device-probe
```

人工实机步骤：Windows 配对手机 → 车机选择“连接音乐” → 确认“手机音频已接通” → 手机播放/暂停与调音量 → 车机断开音乐 → 再次连接 → 退出确认连接释放。听音与物理拔插需硬件操作，样本验证不能代替。
