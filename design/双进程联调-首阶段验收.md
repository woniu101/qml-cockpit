# 双进程联调：首阶段实现与验收

日期：2026-11-02。按用户确认的双仓库目录实施，当前为开发调试版本。

后续已增加电脑电池映射与真实网络信息，见 [Windows 电量与网络接入验收](Windows电量与网络接入-验收.md)。双进程协议和独立构建方式保持兼容。

## 已实现

| 部分 | 当前行为 |
|---|---|
| 独立程序 | 车机 `CarTerminal.exe` 与控制台 `VehicleSimulator.exe`，分别构建，无源码跨仓库引用 |
| 数据选择 | 顶部“数据源”入口、设置入口、连接状态、待处理数量、最新指令和事件日志 |
| 唯一车辆来源 | 外部模式由模拟器推进能量、挡位、车速、里程和车身；车机内部车辆计时停止，避免重复扣电和里程 |
| 实际与目标 | 目标、实际开度、运动标志、请求 ID 和会话分开；拖动只预览目标，3D 玻璃跟随外部实际值 |
| 控制回路 | 请求 → 接受/拒绝 → 连续遥测 → 完成；同部件替换、停止、超时、失联未确认均有反馈 |
| 行驶 | P/R/N/D、速度、里程、耗电、道路和车轮；开始行驶收到有效确认状态后再进入行驶页 |
| 充电 | 开口、插枪、目标、充电/暂停、快进、SOC/续航/功率/预计时间，到达目标自动停止 |
| 车身 | 四门四窗、锁车、前后备厢、后视镜、充电口；服务端校验驻车与开合互锁 |
| 连接异常 | 过期/断开保留最后值，限制外部控制并暂停道路/车轮；约每秒重连，完整快照恢复后启用 |
| 导航 | 使用模拟器累计前进距离，短暂失联后补算同会话内的行驶距离；新会话重新建立基准 |
| 模式恢复 | 切回内置恢复进入前的本地车辆数据，保留当前本地音乐、空调、灯光及显示设置 |
| 控制台 | SOC、四窗实际值注入、四门、挡位/速度、充电、故障开关与日志；未编辑的输入框失焦不会覆盖较新的外部数据 |

本地通信使用长度前缀 JSON、协议版本和会话 ID。窗口实际开度是连续反馈；车门/备厢采用开合状态与执行标志，动画角度仍在车机插值。

## 验证与证据

- 两个仓库均通过 MSVC / Qt 6.12.0 Release 构建。
- 车机 `VehicleStateTests`、`VehicleLinkTests`：状态、分帧、非法数据、版本、会话、快照序号、回执及有在途请求时退出的清理。
- 模拟器 `SimulatorTests`：连续窗位、停止、范围、行驶互锁、能量、充电目标和快照结构。
- 控制台真实鼠标/键盘测试（100% 和 125%）：SOC、四窗输入、未编辑失焦保护、车门互锁和 D 挡行驶。
- 双进程真实 QML 操作：SOC/速度同步、四窗 0/15/50/100%、目标与实际分离、停止与替换、3D 实际玻璃、充电至目标、拒绝、不回执超时、延迟执行、超时后迟到的实际反馈、遥测过期/冻结、同会话导航补算、服务进程退出/重启，以及切回内置时保留音量。
- 两档界面缩放：100% 和 125%；测试使用独立服务名并隔离车机偏好。
- 原有内置 basic 回归及 125% 默认渲染回归通过，覆盖导航、充电、真实本地音乐、门窗、D/R 行驶和原有交互；此次未重跑长时间自动演示浸泡测试。

开发期证据：车机 `artifacts/link/native.log`、`dpi125.log`、`builtin-test.log`、`builtin-native.log` 及对应截图目录；模拟器 `artifacts/ui-smoke.log`、`simulator-console.png`。这些文件均不提交 Git。

默认渲染回归中的本机测量（125%）：行驶标准画质平均约 59 FPS；标准静态交互场景约 48 FPS，高画质约 39 FPS。此为本机一次短测，不能代表其他设备性能。

## 启动与复验

先在两个仓库分别执行 `scripts/build.cmd`，再于车机仓库执行：

```powershell
.\scripts\run-with-simulator.ps1
```

单独启动也可：两端分别执行 `scripts/run.cmd`，车机顶部选择“外部模拟器”。两端默认名称均为 `qml-cockpit.vehicle.v1`。

```powershell
# 车机仓库
.\scripts\test.cmd
.\scripts\verify-link.ps1
.\scripts\verify-link.ps1 -Scale 1.25
# 模拟器仓库
.\scripts\test.cmd
```

协议详见 [vehicle-protocol-v1.md](../docs/vehicle-protocol-v1.md)。测试自动创建并清理自己的模拟器进程，不影响默认服务上的演示实例。

## 后续阶段

1. Windows 电源适配：笔记本 SOC/供电/充电状态、无电池台式机降级、状态未知/过期处理；真实电量来源停止虚拟扣电及充电控制。
2. Windows 网络与蓝牙：网络类型、连接和能力探测；真实手机音频接收另做设备与系统能力验证。
3. 模拟器扩展：完整车身控制台、空调/灯光远端信号、场景脚本、倍率/单步和录制回放。
4. 对内置模型和外部模型做后续规则复用整理。目前两个仓库独立维护模型，协议负责互操作，未建设跨仓库共享库。

当前 Windows 电池、蓝牙和网络图标尚未接入系统；灯光、空调、座椅及音乐保留车机本地逻辑。外部模式暂不运行原有自动演示，避免自动演示快照与外部车辆状态互相覆盖。来源选择每次启动默认内置，可用 `--external` 显式启动外部模式。

本阶段不生成便携包，也未代为提交或推送 GitHub。
